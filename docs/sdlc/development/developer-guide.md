<!-- sdlc:auto:start overview -->
ExpenseTrack is an expense-claims app for small companies (roles: Employee, Manager, Finance), generated by the Quorq AI SDLC platform as two applications in one repository. `frontend/` is a Vite + React 19 single-page app using React Router, TanStack Query and Tailwind CSS 4. Its screens are Sign in, Reset password, Dashboard, Claim, Help and Users, and they still render seeded sample data. `frontend/src/lib/api.ts` provides the `apiFetch` client, which sends a bearer token stored in localStorage. `backend/` is a FastAPI 0.115 service using SQLAlchemy 2.0 and Alembic. On startup it runs migrations to head and can seed a first Finance admin. It currently implements authentication (login, logout, current user, and password reset request and confirm) and Finance-only user administration (list, create, patch, deactivate), plus the `/health` and `/api/healthz` probes. Claims, approvals, categories and receipts are not implemented in the backend yet. The backend's README and `main.py` docstring describe it as health-check-only or stubs, but the routers contain real handlers. The database defaults to local SQLite (`sqlite:///./app.db`); set `DATABASE_URL` to use PostgreSQL 16, which `docker-compose.yml` can provide. Deployment runs through GitHub Actions: the API image goes to ECR and the frontend goes to AWS Amplify.

<!-- sdlc:auto:start setup -->
1. cd backend
2. python -m venv .venv && source .venv/bin/activate
3. pip install -r requirements.txt
4. export BOOTSTRAP_ADMIN_EMAIL=admin@example.com BOOTSTRAP_ADMIN_PASSWORD=change-me-please  # optional: seeds a first Finance user on startup
5. uvicorn app.main:app --reload  # runs Alembic migrations to head, then serves on http://localhost:8000
6. (optional, PostgreSQL instead of SQLite, from the repo root in a new terminal) docker compose up -d db && export DATABASE_URL=postgresql+psycopg://app:app@localhost:5432/app  # then restart uvicorn
7. (new terminal) cd frontend
8. npm install
9. npm run dev  # Vite dev server on http://localhost:5173; calls the API at VITE_API_BASE_URL, defaulting to http://localhost:8000

<!-- sdlc:auto:start conventions -->
- Backend: one APIRouter per component in app/routers/, all under the /api prefix. Finance-only routes are guarded by a router-level Depends(require_finance).
- Pydantic request models are named *In and response models *Out. Write models use extra="forbid", and roles are Literal["Employee","Manager","Finance"].
- SQLAlchemy 2.0 typed models (Mapped/mapped_column) use only portable types so SQLite and PostgreSQL both work. Schema changes go through Alembic migrations.
- Emails are stored lowercased. Only hashes of session and reset tokens are persisted, and passwords are hashed with argon2.
- Auth is a bearer token: login returns a token in the response body, and the frontend stores it in localStorage (`session_token`). apiFetch sends it, and a 401 on a non-public path clears it and redirects to /sign-in.
- Configuration comes from environment variables. Backend: DATABASE_URL, ALLOWED_ORIGINS, BOOTSTRAP_ADMIN_EMAIL, BOOTSTRAP_ADMIN_PASSWORD, RESET_TOKEN_MINUTES, FRONTEND_BASE_URL. Frontend build time: VITE_API_BASE_URL, VITE_API_SECRET_KEY.
- Frontend imports use the `@/` alias for src/. Screens live in src/screens/ (PascalCase) and shared code in src/lib/.
- Styling uses Tailwind CSS 4 utility classes plus brand CSS variables (e.g. var(--brand-surface)) defined in index.css and brand.ts.
- TypeScript is strict, but with noImplicitAny and strictNullChecks disabled.
- Linting and formatting: ESLint and Prettier on the frontend, Ruff (ruff.toml) on the backend. `npm run lint` is a platform gate and must stay green.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| The browser blocks API calls with a CORS error. | With ALLOWED_ORIGINS unset, the API only allows http://localhost:5173 and http://127.0.0.1:5173. Use the Vite dev server on those origins, or set ALLOWED_ORIGINS (comma-separated) to your frontend origin and restart uvicorn. |
| Nobody can sign in on a fresh database, because there is no self sign-up. | Set BOOTSTRAP_ADMIN_EMAIL and BOOTSTRAP_ADMIN_PASSWORD before starting the backend. A Finance admin is created once on startup, and that user can then create other users via /api/users. |
| The frontend screens show sample data instead of your backend data. | This is expected. The screens still render seeded data, and wiring each screen to apiFetch in src/lib/api.ts is outstanding work. |
| `pytest` fails with `ModuleNotFoundError: app`. | Run pytest from inside backend/, where pytest.ini sets pythonpath=. and testpaths=tests. |
| `npm run test:e2e` cannot start the backend. | The Playwright webServer runs `../backend/.venv/bin/python`. Create backend/.venv and run `pip install -r requirements.txt` inside it, or set E2E_BASE_URL to an already-running app. |
| `npm run build` succeeds but the code has type errors. | `vite build` does not typecheck. Run `npm run typecheck` and fix the errors (often an untyped useState({})). |
| The frontend calls localhost after deployment. | VITE_API_BASE_URL is inlined at build time. Make sure it is set in the environment of the build step, as deploy.yml does. |
| You want PostgreSQL instead of the default SQLite app.db. | Run `docker compose up -d db`, set DATABASE_URL=postgresql+psycopg://app:app@localhost:5432/app (psycopg 3 is in requirements.txt), and restart. Migrations run on startup. |
| Security: deploy.yml hardcodes VITE_API_SECRET_KEY / NEXT_PUBLIC_API_SECRET_KEY, and the value is baked into the public frontend bundle. | Treat that value as public, not secret. Rotate it, and move it to a GitHub Actions secret or drop the shared-secret fallback in apiFetch in favor of per-user session tokens. |
| Password-reset links point to the wrong host. | Set FRONTEND_BASE_URL. Without it, the link uses the first ALLOWED_ORIGINS entry, then falls back to http://localhost:5173. |
